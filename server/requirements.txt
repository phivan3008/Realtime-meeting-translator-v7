# ---------------------------------------------------------------------------
# Pipeline requirements - Windows machine, CPU only - Python 3.11
#
#     py -3.11 -m pip install -r server/requirements.lock.txt
#
# The meeting pipeline runs here, next to the client. The GPU pod only
# serves the two big models over HTTP (gpu_server/requirements.txt):
# Whisper behind gpu_server/whisper_server.py and Gemma 4 behind vLLM. So
# vllm and faster-whisper are not installed here, and torch is the CPU build
# - the default torch wheel on Windows from PyPI is CPU-only.
#
# What still runs here, on CPU: Silero VAD, the Overlap Resolver
# (pedalboard), ECAPA voiceprints and VoxLingua107 LID (SpeechBrain), and
# the AST noise filter when ENABLE_NOISE_FILTER=1.
#
# These are the direct dependencies only. server/requirements.lock.txt holds
# the full resolved set for Windows x86_64 / cp311. The versions are the ones
# the pod ran the same stages with, so the move changes the machine and not
# the libraries.
# ---------------------------------------------------------------------------

# --- Web / streaming ---
fastapi==0.136.3
uvicorn[standard]==0.52.4
websockets==17.0.1
# Model downloads verify HTTPS against the Windows certificate store, not
# certifi's bundle: on a network that inspects HTTPS only the system store
# holds the root that signs huggingface.co. See server/tls.py.
truststore==0.10.4

# --- DSP / array math ---
numpy==2.3.5
soxr==1.1.0
scipy==1.17.1
soundfile==0.14.0

# --- Torch stack (CPU) -----------------------------------------------------
# These two must move together. torchaudio is compiled against a specific
# torch ABI, and pip will happily resolve a mismatched pair because its
# metadata does not pin torch tightly enough. A resolver run that produced
# torch 2.13 with torchaudio 2.11 is what put them here as explicit pins.
#
# torchaudio on Windows is the one risk in this file: an earlier client
# environment on this machine failed to load its DLL. The real tests of the
# VAD, the speaker and the LID stages are what prove this set loads here.
torch==2.11.0
torchaudio==2.11.0

# --- 1. Voice Activity Detection -------------------------------------------
silero-vad==6.2.1
onnxruntime==1.29.0        # optional ONNX backend for Silero VAD

# --- 2. Deep Noise Filter: AST (AudioSet) - off by default -----------------
# See server/pipeline/noise.py for why AST and not YAMNet. In short: YAMNet
# means TensorFlow, TF pins numpy < 2.1 and protobuf 4.x, and everything else
# on this list needs numpy >= 2. Same version the pod runs for vLLM, so the
# AST stage loads the checkpoint with the library it was measured with.
transformers==5.14.1

# --- 3. Overlap Resolver (DSP) ---
pedalboard==0.9.24

# --- 4. Speaker Diarization / voiceprint, and 5. Language ID ---
# Both stages use SpeechBrain checkpoints. Voiceprints are ECAPA-TDNN
# (speechbrain/spkrec-ecapa-voxceleb), language ID is VoxLingua107.
speechbrain==1.1.0

# --- 6. ASR and 7. Translation ---------------------------------------------
# Nothing to install: both are HTTP calls to the GPU pod, made with the
# standard library. ASR_BACKEND=local would need faster-whisper==1.2.1 and a
# GPU this machine does not have.

# --- Utilities ---
python-dotenv==1.2.3
rich==15.0.0

# ---------------------------------------------------------------------------
# What binds what
#
# torch decides torchaudio; speechbrain and silero-vad take whatever torch is
# there. numpy >= 2 follows from torch 2.11. transformers stays on the pod's
# pin for the reason given above.
#
# To re-resolve after editing:
#   uv pip compile --python-version 3.11 #       --python-platform x86_64-pc-windows-msvc #       --constraint gpu_server/requirements.lock.txt #       server/requirements.txt -o server/requirements.lock.txt
# ---------------------------------------------------------------------------
